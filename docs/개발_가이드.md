# 개발 · 배포 가이드

이이공이(2202) 내부용 문서입니다. 협회 담당자용 문서는 [CMS_사용법.md](CMS_사용법.md) 를 참고하세요.

---

## 1. 환경변수

`.env.example` → `.env.local` 복사 후 작성합니다.

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | ✅ | PostgreSQL 연결 문자열 (Neon) |
| `SESSION_SECRET` | ✅ | 관리자 세션 서명 키. **32자 이상** |
| `BLOB_READ_WRITE_TOKEN` | ✅ | Vercel Blob 토큰 (첨부파일 업로드) |
| `NEXT_PUBLIC_SITE_URL` | 권장 | 운영 도메인. OG 태그·sitemap 절대경로에 사용 |

`SESSION_SECRET` 생성:

```bash
openssl rand -base64 32
```

> ⚠️ `SESSION_SECRET` 을 바꾸면 기존 로그인 세션이 모두 무효화됩니다(재로그인 필요).

## 2. 데이터베이스 (Neon)

1. [neon.tech](https://neon.tech) 에서 프로젝트 생성 (리전: `ap-southeast-1` 권장)
2. Connection string 복사 → `.env.local` 의 `DATABASE_URL`
3. 마이그레이션 적용

```bash
npm run db:migrate
```

4. 관리자 계정 생성

```bash
ADMIN_PASSWORD='초기비밀번호' npm run admin:create -- --username admin --name "협회 담당자"
```

### 스키마 변경 절차

`src/lib/db/schema.ts` 수정 → 마이그레이션 생성 → 적용:

```bash
npm run db:generate
```

```bash
npm run db:migrate
```

### 무료 티어 참고
Neon 무료 플랜은 유휴 상태에서 컴퓨트가 자동 정지되지만 **요청이 오면 자동 재개**됩니다.
재개 시 첫 요청이 1초 내외 느려질 수 있으며, 별도 조치는 필요 없습니다.

## 3. 파일 저장소 (Vercel Blob)

Vercel 프로젝트 → **Storage → Create → Blob** 생성 시 `BLOB_READ_WRITE_TOKEN` 이 자동 주입됩니다.

로컬 개발 시:

```bash
npx vercel env pull .env.local
```

### 업로드 경로 설계
Server Action은 요청 본문이 기본 1MB로 제한되므로 파일을 액션으로 보내지 않습니다.

```
브라우저 → POST /api/upload (세션 검증 후 업로드 토큰 발급)
        → Vercel Blob 직접 업로드
        → 반환된 URL을 폼 hidden 필드에 담아 Server Action 으로 저장
```

- 허용 형식: PDF, JPG, PNG, WEBP, GIF, HWP/HWPX
- 최대 용량: 파일당 20MB, 글당 10개
- 글 수정 시 목록에서 제외된 파일, 글 삭제 시 전체 첨부파일은 스토리지에서도 삭제됩니다.

## 4. 배포 (Vercel)

1. GitHub 저장소 연결 → Vercel 프로젝트 생성 (Framework: Next.js 자동 인식)
2. **Settings → Environment Variables** 에 위 4개 변수 등록 (Production / Preview 모두)
3. Deploy

### 도메인 연결

Vercel → **Settings → Domains** 에 협회 도메인 추가 후, 도메인 등록기관(가비아·후이즈 등) DNS에 아래 레코드를 등록합니다.

| 대상 | 타입 | 이름 | 값 |
|---|---|---|---|
| `example.or.kr` | A | `@` | `76.76.21.21` |
| `www.example.or.kr` | CNAME | `www` | `cname.vercel-dns.com` |

> 실제 값은 Vercel 대시보드가 표시하는 값을 그대로 사용하세요. 위 값은 변경될 수 있습니다.
> DNS 반영에는 최대 24~48시간이 걸릴 수 있으며, 반영 후 HTTPS 인증서는 자동 발급됩니다.

### 배포 후 확인 목록

- [ ] `/` 랜딩 전 섹션 렌더링 (PC · 모바일)
- [ ] `/board` 목록 · 상세 · 첨부파일 다운로드
- [ ] `/admin/login` 로그인 → 글 등록 → 공개 화면 반영
- [ ] `/robots.txt`, `/sitemap.xml` 정상 응답
- [ ] `NEXT_PUBLIC_SITE_URL` 이 운영 도메인으로 설정되어 OG 태그가 절대경로인지

## 5. 보안 설계 요약

| 항목 | 처리 |
|---|---|
| 세션 | httpOnly + sameSite=lax 쿠키, 운영 환경 secure, 8시간 만료 |
| 비밀번호 | bcrypt (cost 12) |
| 접근 제어 | `src/proxy.ts` 1차 차단 → `(protected)/layout.tsx` 세션 검증 → 각 Server Action `requireAdmin()` |
| 로그인 시도 제한 | 10분 내 8회 (인메모리, `src/lib/rate-limit.ts`) |
| 본문 XSS | 저장 전 `sanitize-html` 로 태그·속성 화이트리스트 정제 |
| 업로드 | 세션 검증 + 확장자/용량 제한 |
| 관리자 노출 | `robots.ts` 에서 `/admin`, `/api` 차단 + 페이지 메타 `noindex` |

> **인메모리 rate limit 한계**: 서버리스에서는 인스턴스별로 카운터가 분리됩니다.
> 단일 관리자 계정 + 소규모 트래픽 기준의 1차 방어선이며, 강화가 필요하면 Upstash Redis 로 교체하세요.

## 6. 알려진 제약 / 범위 밖 항목

- **회원사(성공사례)는 CMS가 아닌 `src/content/members.ts` 데이터 파일로 관리**합니다.
  견적 범위의 CMS 게시판은 1개(공지사항·재무고시)입니다. 회원사 관리 CMS는 별도 견적 대상입니다.
- 개인정보처리방침은 협회 문안 확정 전까지 안내 문구만 노출합니다 (`src/app/privacy/page.tsx`).
- 문의 폼은 범위 밖입니다. 필요 시 이메일 링크 또는 네이버 카페 링크로 대체합니다.
- SEO는 기본 메타태그·OG·sitemap 까지만 포함하며, 마케팅·애널리틱스 세팅은 범위 밖입니다.
